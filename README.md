## What runs through all of them

- **Out-of-sample by construction.** Walk-forward refits (project 2),
  chronological splits (project 8), machine-grouped folds (project 5) and
  nested threshold selection. Every look-ahead risk has a test that changes
  future data and checks that past outputs don't move.
- **Honest statistics.** Newey-West errors for overlapping windows, correct
  Engle-Granger critical values (checked by Monte Carlo), bootstrap
  intervals, false-discovery control and power analysis.
- **Costs and execution.** Every strategy is reported before and after costs,
  with the cost assumptions varied.
- **Checked against something independent.** Closed-form results, put-call
  parity against futures (1.7 bps), known market events, and an independent
  re-pricing of real trades (0.96 correlation). One such check exposed a
  hedging bug in the first version of project 7, which is documented.
- **Negative results reported.** No FX pairs edge, no taker edge in order-book
  imbalance, no benefit from a VIX filter.

## Run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r 07_nifty_volatility_risk_premium/requirements.txt   # or any project's requirements
python run_tests.py          # all 83 tests, no pytest needed
./reproduce.sh               # regenerate every dataset, result table and figure, then test
```

Inside any project folder `pytest -q` also works. GitHub Actions runs each
project's tests on every push.

## Repository layout

```
<project>/
  README.md          question, method, results, validation, limits
  src/               code; each script runs from any directory
  tests/             pytest-compatible tests
  data/              datasets + SOURCES.md (real data) or generators (synthetic)
  results/           generated tables, including summary.md
  plots/             generated figures
run_tests.py         test runner across projects
reproduce.sh         end-to-end regeneration
CHANGES.md           what changed in each version and why
```
